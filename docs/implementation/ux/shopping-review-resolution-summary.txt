2. WHY "BERRIES" HAD NO VISIBLE RESOLUTION PATH
------------------------------------------------
The disambiguation UI already existed in the expanded detail pane
(WorkspaceRow lines 848–984), including suggestion chips, multi-select,
and confirm flow. The problem was discoverability:

- In Review mode, the CTA slot showed a generic "Analyse" button for
  every item — including ambiguous ones
- There was no visual difference between a normal item and one that
  needs disambiguation
- The user had to know to click the chevron/row to expand it before
  they'd see the "Ambiguous — which did you mean?" section
- Additionally, the /correct endpoint didn't re-run resolveItem, so
  after picking a suggestion, needsReview and reviewReason stayed as
  "ambiguous_term", causing the "Choose item" button to persist on
  the resolved item
