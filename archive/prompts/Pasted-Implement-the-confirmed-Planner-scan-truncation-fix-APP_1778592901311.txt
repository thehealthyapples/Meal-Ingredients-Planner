CONFIRMED ROOT CAUSE
Planner scans can exceed the shared 2000-token OpenAI output limit.

When this happens:

* vision output is truncated
* JSON.parse fails
* extractWithVision returns null
* extractDestination silently falls back to OCR/heuristic
* lunch ideas disappear
* shopping items disappear
* richer context disappears

REQUIRED FIX

1. Planner-only token budget

Use a higher output token limit ONLY for mode="planner".

Suggested:

* planner: 4096 or 6000
* recipe/shopping_list: unchanged

Do not globally raise token limits.

2. Explicit finish_reason handling

Read:
response.choices[0]?.finish_reason

If finish_reason === "length":

* treat this as truncation
* do NOT silently continue as normal
* emit a clear warning in the parsed response
* log it in dev with [planner-scan-debug]
* preserve user-facing trust state

3. Prevent silent fallback masking truncation

If planner vision truncates:

* do not silently fall back to OCR as though normal
* either retry once with the higher planner token budget if this occurs after a first attempt
  OR
* return a clear planner scan warning that the result was incomplete

Preferred:

* planner mode should use the higher token budget on first attempt
* fallback should only be used for genuine vision failure, not hidden token truncation

4. Keep fallback but classify it correctly

OCR fallback can remain for:

* vision API failure
* invalid response not due to token length
* image unreadable

But:

* fallback must add a warning like:
  “Detailed planner interpretation was unavailable, so THA used a simpler scan result.”

Do not expose technical wording like:

* token limit
* JSON parse
* OpenAI failure
  in primary user-facing messages.

5. Preserve mode isolation

Only planner scans should change.

Confirm recipe and shopping-list scans still use existing token behaviour.

6. Verify no client-side changes are required unless needed for warning display

The client already supports:

* planned meals
* lunch ideas
* shopping items

Do not redesign UI.

7. Keep debug logs controlled

Keep useful [planner-scan-debug] logs in development only.

Do not log:

* uploaded image
* personal data
* full user content in production
